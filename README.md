# Daybreak Coffee Co. — Website with QR Ordering

A full-stack coffee shop website:
- **Landing page** (`/`) — hero section, menu preview, and a QR code for ordering.
- **Order page** (`/order`) — what customers land on after scanning the QR code. Menu is pulled live from the database, customer builds a cart, and submits the order.
- **Kitchen dashboard** (`/admin`) — see incoming orders in real time and update their status.
- **Database** — SQLite (`coffee_shop.db`), a single file, no separate database server needed. Auto-created and seeded with sample menu items the first time you run the server.

## 1. Requirements
- [Node.js](https://nodejs.org) v18+ installed.
- VS Code (or any editor).

## 2. Open in VS Code
1. Unzip the project folder.
2. In VS Code: `File → Open Folder…` → select `coffee-shop`.
3. Open a terminal in VS Code: `` Terminal → New Terminal ``.

## 3. Install dependencies
```bash
npm install
```

## 4. Run the server
```bash
npm start
```
You'll see:
```
☕ Coffee shop server running at http://localhost:3000
   Order page (what the QR code links to): http://localhost:3000/order
   Kitchen/admin dashboard: http://localhost:3000/admin
```

Open `http://localhost:3000` in your browser to see the site.

## 5. Generate the QR code
The QR code image on the homepage is generated by:
```bash
npm run generate-qr
```
This creates `public/qr-code.png`, pointing at `http://localhost:3000/order`.

**Important for real customers:** `localhost` only works on your own computer. For a QR code customers can actually scan on their phones:
1. Deploy the site somewhere public (see "Going live" below), **or**
2. Use a tunnel tool like [ngrok](https://ngrok.com) for testing: `ngrok http 3000`, then run:
   ```bash
   ORDER_URL=https://your-ngrok-url.ngrok.io/order npm run generate-qr
   ```
3. Print the resulting `public/qr-code.png` and place it on your tables.

Until you generate a real QR code, the homepage automatically falls back to a QR code generated on the fly (via a free QR API) so you always see something scannable during development.

## 6. How data flows into the database
- `database.js` creates three tables on first run: `menu_items`, `orders`, `order_items`.
- The order page (`public/js/order.js`) calls `GET /api/menu` to show items, and `POST /api/orders` to save a new order.
- `routes/orders.js` writes the order and its line items into SQLite inside a transaction.
- The kitchen dashboard (`public/admin.html`) polls `GET /api/orders` every 15 seconds and lets staff update status via `PUT /api/orders/:id/status`.

## 7. Customizing
- **Menu items:** edit the seed list in `database.js`, or delete `coffee_shop.db` and restart the server to reseed. You can also add items via `POST /api/menu`.
- **Branding/colors:** edit CSS variables at the top of `public/css/style.css`.
- **Shop name/images:** edit `public/index.html`.

## 8. Going live (optional)
To make this reachable by real customers scanning a QR code:
- Deploy to a host like Render, Railway, Fly.io, or a VPS (all support Node.js + a persistent file for SQLite).
- Set the `PORT` environment variable if your host requires it (already handled in `server.js`).
- Re-run `npm run generate-qr` with `ORDER_URL` set to your live domain, then print the QR code.
